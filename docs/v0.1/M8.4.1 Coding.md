# 3. 本轮必须回答的三个问题

## Q1：20 个 storage read 是否存在真实 dependency？

必须回答：

```text
storage #1
storage #2
...
storage #20
```

之间究竟属于：

```text
independent
ordered
unknown
```

三种之一。

### 定义

#### independent

可以证明：

> B 的请求是否发起以及 B 的请求参数，不依赖 A 的返回值。

#### ordered

可以证明：

> B 必须等待 A，因为 B 的请求参数、是否发起或者语义依赖 A 的结果。

#### unknown

当前证据不足。

**unknown 不允许自动推导成 independent。**

# 28. 最重要的原则

这一轮请始终遵守：

> **不知道，就记录 unknown；**
>
> **没有测到，就记录 not observed；**
>
> **没有证明 dependency，就不能说 independent；**
>
> **没有证明性能改善，就不要称为 optimization。**

M8.3.3 已经证明了：

```text
serial RPC
      ↓
bounded concurrency
      ↓
确实可以降低 wall-clock latency
```

M8.4.1 要解决的是下一层：

```text
为什么剩下的 RPC 还要这样执行？
哪些真的有 dependency？
哪些只是当前实现恰好串行？
整条 pipeline 又在哪里继续浪费时间？
```

**不要在本轮直接回答“应该怎么优化”。先把证据做完整。**
