# M8.2 Coding Task — Simulation State Acquisition Diagnosis

## 1. 任务定位

项目：`fenglufa/evm-mev-bot`

当前阶段：M8 Hardening

上一阶段：

* M7 Real Arbitrage：COMPLETE
* M8.1 Latency Instrumentation & Baseline：INCOMPLETE，但 instrumentation 本身已经完成并验证
* 当前任务：**M8.2 Simulation State Acquisition Diagnosis**

M8.2 的唯一目标：

> **回答：为什么真实 GIWA simulation 阶段需要约 20–25 秒？**

目前 M8.1 已经证明：

```text
Live opportunity lifecycle
        ↓
Simulation 是主要耗时阶段
        ↓
Simulation 被正确归类为 mixed
        ↓
原因与 RPC / chain state acquisition 高度相关
```

但是目前仍然不知道：

* Simulation 实际进行了多少次 RPC
* 各种 RPC 分别占多少
* 每次 RPC 花费多少时间
* RPC 是否主要串行
* 是否存在重复读取
* 哪些 state read 可以复用
* 哪些等待来自 provider / connection / node
* 哪些时间是真正的 REVM 本地计算
* 哪些时间是 RPC state acquisition

因此：

> **M8.2 只做诊断，不做优化。**

# 9. Serial / Overlap Diagnosis

必须判断 RPC 是否存在重叠。

如果：

```text
RPC A:
0ms → 500ms

RPC B:
500ms → 900ms
```

则：

```text
serial
```

如果：

```text
RPC A:
0ms → 500ms

RPC B:
20ms → 400ms
```

则：

```text
overlap
```

至少计算：

```text
rpc_wall_time
rpc_sum_duration
overlap_duration
serial_wait_duration
```

定义：

```text
rpc_sum_duration
```

是所有 RPC duration 之和。

```text
rpc_wall_time
```

是：

```text
last_rpc_end - first_rpc_start
```

如果没有 RPC：

```text
null
```

不要填 0。

# 11. Local computation measurement

Simulation 至少应该能够区分：

```text
simulation_total_duration
rpc_wall_duration
rpc_sum_duration
non_rpc_duration
```

注意：

不能简单：

```text
non_rpc = total - rpc_sum
```

如果 RPC 存在 overlap，这个计算会错误。

应基于 interval union / timeline 计算。

例如：

```text
Simulation:
0 ───────────────────────── 1000ms

RPC A:
0 ─────── 500

RPC B:
200 ───────── 700

RPC C:
800 ───────────── 1000
```

RPC union：

```text
0 → 700
800 → 1000
```

RPC wall coverage：

```text
900ms
```

因此：

```text
non_rpc = 100ms
```

而不是：

```text
1000 - (500 + 500 + 200)
```

# 36. 最重要的工程原则

整个任务遵循：

```text
Measure
  ↓
Attribute
  ↓
Diagnose
  ↓
Evidence
  ↓
Optimize later
```

而不是：

```text
Measure
  ↓
Guess
  ↓
Optimize
```

M8.2 的成功标准不是让 simulation 变快。

而是让我们能够用证据回答：

> **“这 24 秒到底花在哪里？”**

只有这个问题被可靠回答以后，才进入 M8.3。
