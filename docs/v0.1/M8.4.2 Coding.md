# 4. 核心概念：什么叫“重复 RPC”

必须区分：

### 4.1 Exact duplicate

两个 RPC 满足：

```text
method 相同
chain_id 相同
block/tag 相同
target/address 相同
slot 相同（如适用）
参数语义相同
```

例如：

```text
eth_getBalance(A, block X)
```

在 detection 和 preflight 各出现一次。

这是最强的重复证据。

---

### 4.2 Semantic duplicate

请求参数字面形式可能不同，但语义完全相同。

例如：

```text
0x1
```

和：

```text
"0x000...001"
```

如果代码能够证明它们代表同一个 block/slot/address，可以归入 semantic duplicate。

但：

> **不能靠字符串猜测。**

---

### 4.3 Same target, different block

例如：

```text
getBalance(A, block 100)
getBalance(A, block 101)
```

不是 duplicate。

必须标记：

```text
same_target_different_block
```

不能算可复用。

---

### 4.4 Same method, different semantics

例如：

```text
getTransactionCount(A, latest)
getTransactionCount(A, pending)
```

不能算 duplicate。

# 6. 必须区分三个概念

这是本轮最重要的规则。

## A. Duplicate

两个 stage 请求了相同的数据。

## B. Reusable

数据相同，而且 consumer stage 理论上可以使用 producer stage 的结果。

## C. Safe-to-reuse

代码和生命周期证据都证明：

```text
block identity 相同
state semantics 相同
生命周期允许复用
没有 freshness requirement
```

只有 C 才能进入：

```text
safe_reuse = true
```

因此：

```text
duplicate ≠ reusable
reusable ≠ safe-to-reuse
```

# 35. 最终不要预设结果

这一点和 M8.3.3 一样重要。

可能出现：

```text
结果 A：
跨 stage 几乎没有重复
```

那么结论就是：

> pipeline RPC reuse 不是主要优化方向。

也可能：

```text
结果 B：
发现大量 exact duplicate
```

那么下一步才研究：

> controlled cross-stage state reuse。

也可能：

```text
结果 C：
大量 duplicate，但 block/freshness/lifecycle 无法证明
```

那么：

> 先研究 state ownership / lifecycle，而不是直接加 cache。

甚至可能：

```text
结果 D：
Preflight → Build
Detection → Simulation
```

出现明显重复，而其他阶段没有。

那下一轮就只针对这个路径做实验。

**不要为了证明“应该做 cache”而设计实验。**
