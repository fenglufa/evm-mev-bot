**一句话结论：11 类链上状态逐类问了一遍「谁产生、谁拥有、属于哪个生命周期、什么让它失效、下游因此能消费什么」，4 类的 owner 与身份说得清、7 类只能说清一半；23 条阶段边判完是 A 2 / B 5 / C 16 / D 0；M8.4.2 记录的 42 个重复候选按本模型的四级判定，0 条到达 `safe_to_reuse_now`，且每行都点名了拒绝原因。本轮按 §17 收口在 A：只有 `block_header` 一类具备设计一个受控复用实验所需的条件，缺的是「一个同时带 number 与 hash 的载体」，不是缓存。**

- 里程碑：M8.4.3 State Ownership & Lifecycle Diagnosis
- 任务书：`docs/v0.1/M8.4.3 Coding.md`（§1–§17）
- 性质：**diagnosis only**。没有新增缓存、没有跨 stage 复用、没有改 `StateReadCache` 命中范围、没有改 RPC 次数/顺序/并发、没有 batch/multicall/prefetch、没有改 REVM 取语义、没有改机会识别/利润/Risk/执行行为、没有改 nonce/fee/gas/余额/选块规则、没有签名与广播（§3）。发现的边界**只记录，不消除**。
- 证据：`data/evidence/m8/state-ownership/`（5 份文件，全部由一次装配写出）
- 输入：M8.4.2 已提交的三把 live BuildOnly run 与固定块两臂（`data/evidence/m8/cross-stage/`）。**本轮没有跑任何新实验，一次 RPC 都没有多问**（§11）。

## 白话版（给不看代码的人）

把一条流水线想成四个工人：接线员（连接节点）、看板人（发现机会）、门卫（preflight 十项检查）、下单人（build）。同一个问题被两个人各问一次节点，不一定是浪费——**只有当两个人问的是同一件事、答案属于同一段生命周期、而且这段时间里没人动过它，才谈得上省一次问**。

本轮给每一样被问的东西建了一张卡片：谁第一个拿到（owner）、这张卡片管到哪一步（scope）、什么时候算过期（freshness）、谁会把它作废（invalidation）、以谁的回答为准（authority）。11 张卡片里有 2 张连"谁拿着"都填不出来（余额、`eth_call` 的结果：代码里确实没有一个组件在两站之间持有它）；填得出 owner 的卡片里，**过期规则能证明的 7 张、作废规则能证明的只有 3 张**。

结果不是"能省多少"，而是画出了边界：42 个"看起来重复"的读取，被逐个判定，**没有一个可以安全共享**——最常见的一档原因是七条并列的硬缺（答案字节没记录、block hash 没记录、失效规则未证明、同值不同来源、状态移动检测不到、契约缺证据、跨生命周期），每条 42/42 行都命中。

## 2. 状态类别与所有权矩阵（§4）

11 类逐类声明，`ownership_status`：**proven 4 / partially_proven 7 / unknown 0**。四行是「owner、scope、身份三样都说得清」的（`contract_code`、`storage_slot`、`block_header`、`chain_identity`）。

owner 的分布本身就是一条结论：`no_owner_in_code` 出现 **2 次**（`native_balance`、`eth_call_result`）——不是"没查到"，是代码里确实没有组件在站与站之间持有这份答案。

| 字段 | 分布 |
|---|---|
| owner | `simulation_state_provider` 3、`no_owner_in_code` 2，其余 6 类各 1（`state_store`、`execution_lane`、`chain_adapter`、`chain_adapter_connection`、`node`、`sequence_stage`） |
| 状态身份形式 | `height_number` 4、`height_hash` 3、`tag` 2、`no_block_term` 1、`not_block_scoped` 1 |
| authority | `node_at_height` 7、`node_canonical_logs` 1、`first_answer_at_connect` 1、`configuration` 1、`not_applicable` 1 |
| freshness 规则 proven | **7 / 11** |
| invalidation 规则 proven | **3 / 11** |

三条关键区分，按 §4 与 §8 的要求写成契约内容而不是口号：

- **StateStore / GraphSnapshot ≠ REVM canonical state。** `pool_reserves` 的 authority 是 `node_canonical_logs`（日志应用出来的投影），快照带一个已应用高度但没有 block hash；REVM 问的是链上持有什么。两条边（`s8.canonical_state.store_is_not_an_evm_source`、`s7.pool_reserves.finding_to_simulation`）都判 C。
- **tag 不是明确高度。** `native_balance`、`nonce` 两类的身份形式是 `tag`：两次一模一样的问法是两个时刻的两次采样，不是一个状态的两次消费。模型只记 term 的**种类**（number / tag / absent），`latest` 与 `pending` 这两个词由记录原样带在 `source_record` 里——因为 `src/` 下不许出现那个标签字面量，这是 `crates/pipeline/tests/state_is_always_pinned.rs` 的 §20 禁令，门禁不允许诊断文件豁免。
- **`chain_identity` 不属于任何区块生命周期。** 它的身份是端点连接属性（`first_answer_at_connect`，作用域 `chain`），本轮三把 run 里它的 6 对重复两侧完全等值；判不到 `safe_to_reuse_now` 的原因不是"不确定"，而是那两个 consumer 各自是一份执行前检查。

## 3. 生命周期与失效规则（§5）

55 行 = 11 类 × 5 步（`acquired`、`validated`、`published`、`consumed`、`invalidated_or_expired`），每步都答了「谁做的、凭什么、留下了什么证据」。

- 状态分布：**proven 33 / partially_proven 11 / unknown 8 / not_applicable 3**。
- `unknown` 的 8 行有明确形状：**7 行卡在 `published` 一步**（`native_balance`、`nonce`、`fee_parameters`、`block_header`、`chain_identity`、`eth_call_result`、`transaction_intent`），1 行卡在 `native_balance` 的 `validated`。用一句白话说：这七类状态被读出来之后，**代码里没有任何"发布"这个动作**——值留在调用栈上，函数返回就没了，所以「发布给谁、以什么版本发布」答不了。
- 没有锚点的行 **10**：`not_applicable` 3 + `unknown` 7。门禁的规矩是单向的——正面的断言必须开得出一个真实文件，答不了才允许空着手。

失效规则只 proven 3 / 11 这一条，是本轮最硬的否定结论：**大部分状态类别在本代码里没有"作废"机制**，不是没记录，是不存在。所以 §6 的「余额/nonce/fee 在 preflight 之后会不会动」这个问题，能回答的是「现在的设计每次重新问一遍，所以不需要作废」；不能回答的是「如果共享了值，什么会作废它」。

## 4. 专项 A：Preflight → Build（§6）

§6 有 13 行边，preflight 作为 producer 的实测重复对合计 **18 对**，其中 preflight → build **12 对**。逐条给结论（一条流一行，绝不是一类状态一个结论）：

| 边 | method | 对数 | 判决 | 这一行的结论 |
|---|---|---|---|---|
| `s6.nonce.preflight_to_build` | `eth_getTransactionCount` | 3 | **C** | 两侧问的是同一个地址同一个 tag，但 tag 指的是节点当时的头；nonce 在 lane 里按设计会前进，拿着旧答案构造下一笔就是另一笔交易。§26 的 nonce 那一腿保留。 |

| `s6.fee.preflight_to_build` | `eth_maxPriorityFeePerGas` | 3 | **C** | 该方法根本不带区块项，答案就是"节点回答的那一刻"的函数。§26 的 fee 那一腿存在的意义就是抓到费用移动，共享值等于给这条腿留下没得比的东西。 |

## 5. 专项 B：Opportunity → Simulation（§7）

4 条边，全部判 **C**，其中两条有实测重复对（`s7.header.observation_to_simulation_pin_read` 3 对）。

- 模拟确实在重新取状态：它那一份固定块臂 run summary 里的 41 次调用（该文件自己的 `source` 列逐行标 `fixture`）中 21 次读 storage 槽，是最大的一组；这些读取属于本次运行自己的状态源。
- 快照（`GraphSnapshot`）不可能成为 REVM 的状态源：它带一个已应用高度，不带 state root、不带 storage、不带 code。跨边递送的是机会身份与路径，不是状态。
- 过期（staleness）由 ledger 在模拟之前决定，重新模拟是一次新 run（新 fingerprint），不是旧 run 的复用；「提交时是否仍然有利可图」由 gate 腿回答。
- 一个高度不等于一个身份——高度 + hash 才是，而代码已经强制这一对（`state_version_mismatch`、`binds_block_at_pin`）。这条 finding 正是 §6 两条 header 边可以判 A 的前提：**实验可以共享一个 header，绝不能共享一个裸高度。**

## 6. 专项 C：State Update → Simulation（§8）

2 条边，判决 **B 1 / C 1**。

- `s8.pool_reserves.snapshot_lacks_a_hash`（B）：store 只有一个写入路径（`apply_update` → `update_position`），replay 与 live 走同一个规范化函数，所以**确定性不缺，缺的是身份**——快照类型里没有 hash 字段，消费方无法说明"我指的是哪个块"。判决 B 的意思是把契约设计出来，而不是加缓存。
- `s8.canonical_state.store_is_not_an_evm_source`（C）：store 答"池子做了什么"，REVM 问"链上持有什么"，两者生产方、owner、authority 都不同，不可互换。这条是 §8 要的 authority matrix 本身。

## 7. 专项 D：Simulation → Build（§9）

4 条边：**C 3 / B 1**。

- 两侧输入字段一致（chain id、target、value、calldata、nonce、gas、fee、access list、sender）——但这是**同一个函数构造出来的**（`from_simulated_step` 是 intent 的唯一来源），不是某项检查证明的；本轮把它记为 B：缺的是一个"从被点名的那次模拟结果重 derive 这些字段再比对"的检查，今天九个字段的比对只对着 intent，没有一个对着模拟。
- 依赖 state override 的模拟结果被**直接拒绝**进入 build（builder 里点名它拒绝了哪笔资金，且发生在任何签名之前）。§9 要的"override 依赖不能当可执行性证据"是 enforced，不是 assumed。
- 多步计划被拒：模拟利润是整条序列的属性，单笔的可构造性不由它推出。
- 余额这一族在这里出现第三种形状：`s9.native_balance.build_gate_leg` 判 C（3 对实测）——模拟那次问的是"这次 run 里的拨款付得起吗"，这一腿问的是"真实钱包在发送前付得起吗"。
