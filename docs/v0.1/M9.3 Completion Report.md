## 1. Executive Summary

**白话版（先看这一段）**

M9.3 做的事，是拿一张「谁能换成谁」的地图（M9.2 在区块 37224031 上重建出来的交易图），
把所有**能回到出发点的闭环路线**挑出来并起个名字。仅此而已。

- 地图上有 50 个代币、160 条有向边、80 个池子。
- 走出来的闭环是 **68 条**：其中 66 条经过 2 个池子（`A → 池1 → B → 池2 → A`），
  2 条经过 3 个池子（绕三个柜子在第三个柜子回到起点）。
- 这 68 条里，**知道费率的有 0 条**。图上 160 条边的费率全是「没人举证过」，
  所以一条都算不出钱——不是算出「不赚」，是**根本没算**（§56 要求写成 `N/A`，不许写 `0`）。
- 搜索一次共检查了 **14860 次有向边**（= 走路的步数，单位是「次」），
  耗时 31–32 毫秒（单位是「毫秒」，只在装配那一次里量）。
- 本里程碑**没有碰网络、没有私钥、没有广播**：搜索 crate 的生产依赖只有 4 个包，
  这 4 个包都开不了 socket，读 `Cargo.toml` 就能核对（§42）。

一句话结论：**M9.3 把「地图上的闭环」这件事实数清楚了，并且一条都没往前一步说成「机会」或「钱」。**
阶梯 `Path ≠ CycleCandidate ≠ Executable Opportunity ≠ Simulated Profit ≠ Executed Profit ≠ Realized Profit`
里，本里程碑只造出第二级。

**判定**：`M9.3 STATUS = COMPLETE`（§27，八组条件逐条给证据）。

## 4. GraphSnapshot Contract

- 入口签名：`find_cycles(&GraphSnapshot, &PathFinderConfig) -> Result<Vec<CycleCandidate>>`
  与 `find_cycles_traced(...) -> Result<PathFinderRun>`（`search.rs:50-59`）。
- 图是**借来的**，不是复制的，更不是可写的：`Search<'g> { graph: &'g GraphSnapshot, ... }`。
  测试 `the_graph_is_read_and_never_written`（`crates/pathfinder/tests/pathfinder.rs:958`）
  在搜索前后各取一次图的字节指纹并断言相等——「能改市场的搜索也能造出一个市场」这条被钉死。
- 读的东西只有三样：`nodes()`、`neighbors(token)`、`routes(from, to)`。
  不读储备、不读 fee 数值（只读「有没有举证」）、不读块外任何状态。

## 5. Path Definition

一条 Path 是**有向边的序列**，写作 `t0 --e0--> t1 --e1--> ... --t(n-1) --e(n-1)--> t0`。
方向是身份的一部分：`A → B` 与 `B → A` 是两条边（不同 `token_in`/`token_out`），
因为反向花的是另一种币。候选里存的是 `Vec<EdgeId>`（`candidate.rs` 的 `edges` 字段），
不是边对象——`GraphEdge` 一次都没被复制进候选。

---

## 6. Cycle Definition

一个 Cycle 同时满足：

1. **闭合**：最后一条边的 `token_out` 等于第一条边的 `token_in`（§6）。
2. **池子不重复**：一条环里同一个 `PoolId` 只许出现一次（§8）。
3. **中间代币不重复**：闭合之前不许二次站上同一个 `TokenId`（§9）。
4. **深度 2..=3**：见 §8。
5. **不是单池自环**：一跳的「环」是拿一个币跟它自己换（§25 的下界）。

这些是 `CycleCandidate::assemble`（`candidate.rs:159`）自带的构造期不变量：
不满足就返回 `None`，搜索层因此是搜索而不是校验器。

---

## 7. Search Algorithm

有界 DFS（`search.rs:98` 的 `Search::walk`，状态在 `:88`），不是最短路算法。理由写在模块注释里：
Bellman-Ford / SPFA 回答的是「怎么去最便宜、有没有负环」，Dijkstra 要求非负权重，
而本层唯一的权重是拓扑——它们都不枚举环、不给确定性命名、也不拒绝重复用池。

形状：

- 对每个起点 `start`（`graph.nodes()` 的 BTree 序）做一次行走；
- 每一步遍历 `neighbors(current)` × `routes(current, next)`，每次边的检查计一次 `states`；
- 拒绝已用过的池；`next == start` 且深度 ≥ 2 时闭合，交给 `assemble`；
- `trail.len() >= max_hops` 直接返回，不剪枝不近似。

结果收集在 `BTreeMap<CanonicalKey, CycleCandidate>` 里，
迭代出来就是任务书 §26 要的排序（**不需要第二次排序**，也不允许 `sort_by_key` 之外的任意性）。
没有任何候选数量上限（§33）：搜到 N 条就停的搜索，报的是它选中的市场，不是它看见的市场。

`states_visited` 只做诊断，**不参与**任何判定（§19 的边界；测试
`search_reports_the_states_it_visited`，`pathfinder.rs:930`）。

## 8. Hop Bound

`config.rs`：`MIN_MAX_HOPS = 2`、`MAX_MAX_HOPS = 3`、`Default = 3`。
越界是**配置错误**：`validate()` 返回 `PathFinderError::MaxHopsOutOfRange { actual }`，
在走第一步之前就拒绝，绝不「按 3 跑但报告说按 100 跑」。
测试 `nc_config_bounds_are_enforced_and_never_silently_widened`（`pathfinder.rs:899`）
+ lib 测试对 `[0, 1, 4, 5, 100]` 逐个验红。

以后要 4 跳属于新里程碑的工作：搜索空间、benchmark、pruning 要单独评估（任务书 §7）。

## 9. Pool Reuse Rule

一条环内每个池子最多进一次。实现：`walk` 里 `if pools.contains(&edge.pool()) { continue }`。
理由（任务书 §8）：同一个恒定乘积池来回进出是捐手续费，不是套利。
证据：NC1（`t07_same_pool_reuse_is_rejected`）。

真实图上这条规则的曝光量：160 条边里有 22 条**没有被任何候选走过**
（`candidate-edges.json#totals`），这是拓扑陈述，不是质量陈述。

---

## 10. Intermediate Token Reuse Rule

闭合之前不许二次站上同一个代币（否则 `A → B → A → C → A` 是两条环被报成一条）。
实现：`tokens: BTreeSet<TokenId>` 在递归进入时插入、返回时移除。
证据：NC2（`t10_repeated_intermediate_token_is_rejected`）、`t11_self_loop_is_rejected`。

---

## 11. Canonicalization

`CanonicalKey::new(edges)` = 在 `EdgeId` 的 `Ord` 下取**最小轮转**（`candidate.rs:35-91`
的 `minimum_rotation`）。轮转折叠的是「同一条环从不同座位出发」：
`A→B→A` 从 A 走和从 B 走记成同一条。

为什么能用字符串重推：`TokenId`/`PoolId` 是 `{chain_id, address}`（`core/identity.rs:35,41`），
地址定长小写十六进制 ⇒ 字典序 == 字节序。证据门的独立重算段正是靠这一点，
只吃已提交行、不叫任何生产函数，就把每条候选的规范键重推了一遍
（`negative-controls.json#recomputed_over_the_real_graph` 的第 8、9 项）。

---

## 12. Rotation vs Reversal

轮转折叠，**反向不折叠**（任务书 §14）。`A→B→C→A` 与 `A→C→B→A` 花的是不同的币，
是两条候选，实测在 2 跳上也一样：NC5（`t14_reversal_is_preserved`）。
真实图 66 条 2 跳候选 = **33 个不同池对 × 每对恰好 2 条**（从已提交的 `cycles.json` 现数出来）——
这个数字与 §17 的 2 跳交叉验证相互咬合（同一批路线由 M9.2 的边表独立数出来）。

---

## 13. Fee Semantics

`FeeStatus { Complete, Incomplete }`（`candidate.rs:101+`）。判定是逐边的：
候选走过的**每条**边的池子都有已举证费率才 `Complete`。

- `None` 不是 0（`t20_none_is_never_zero`）；
- `None` 不是 997/1000（`t21_none_is_never_the_usual_rate`）；
- 一条 `None` 就 `Incomplete`（`t18`），多条同理（`t19`）；
- `Incomplete` 进不了财务层（`t22_incomplete_cannot_be_promoted`）。

本层不解析费率、不默认费率、不猜费率（§16–§18）。
实测：`fee_complete = 0`、`fee_incomplete = 68`（`summary.json`）。
这不是搜索的失败：M9.2 图上 160 条边的 `fee` 字段全是 `null`，
所以「一条都算不出钱」是**输入的事实**，M9.3 把它如实传上来而不是抹平。

## 14. Candidate Schema

`CycleCandidate` 的七个字段（`candidate.rs:127-147`），与任务书 §39 的候选证据 schema 对齐：

`chain_id`、`target_block`、`start_token`、`edges`、`hop_count`、`canonical_key`、`fee_status`
（+ 构造期不变量保证内部一致）。

**禁止出现的字段名**在证据门里是机器核对的：常量 `FORBIDDEN_FIELD_SHAPES`（`pathfinder_evidence_gate.rs:174-185`，
`[&str; 10]`）逐个列出 `arbitrage_opportunit`、`profitable_opportunit`、`opportunities_found`、
`expected_profit`、`optimal_amount`、`gas_cost`、`simulation_status`、`execution_status`、
`amount_in`、`amount_out`，任何一张已提交表或原始记录里出现即红
（测试 `no_candidate_is_named_an_opportunity`，另外还禁两个说法 `found profit`、`pathfinder found`）。

注意禁词表禁的是「利润/机会的**断言**」，不是「利润这个词不许出现」：`summary.json#profit` 里
确实有 `gross_profit`、`net_profit`、`realized_profit` 三个键，它们的值**只能**是字符串 `N/A`

这三个键不在禁词表里，是被 §56 反向要求的内容，门禁因此放行；两者的分工写清楚以免看起来自相矛盾。

## 17. Real Graph Integration（任务书 §36）

零 RPC 地拿到真实图的路径（这是 M9.3 最吃证据的一步）：

1. 读 M9.1 的 `raw/pass-a.json` 与 M9.2 的 `raw/reconstruction-pass-a.json`；
2. 反序列化进 `Reconstruction`，走 `integrate_at_target` + `MarketGraphBuilder` **重建**
   `GraphSnapshot`（不能从 JSON 直接复活快照，见 §4）；
3. **逐边对照** M9.2 已提交的 `graph-integration.json`：本次重建的 160 条边三元组
   与已发布列表按序全等（`the_run_read_the_graph_m9_2_published`）。不等就红，
   消息写明「本次运行重建出了与 M9.2 已提交不同的拓扑」；
4. 在这张图上跑默认配置（`max_hops = 3`）的搜索，产出 §18 的全部表。

实测结果：50 节点 / 160 边 / 80 池 / 目标块 37224031 / 68 条候选 / 0 条费率齐全。
候选覆盖 69 个不同池、138 条边至少被一条候选走过、22 条边一条都没走过。

**2 跳集合的交叉验证（审计 §5 的关系在这里被实测）**：测试
`the_two_hop_candidates_are_exactly_the_routes_in_m9_2s_table` 拿 M9.2 **已提交的边表**
（`data/evidence/m9/m9.2/graph-integration.json` 的 160 条边）在门禁里独立走一遍 2 跳闭合
（`e1: A→B` + `e2: B→A`、池子不同、排除自环），把每条有序边对折成最小轮转，三条断言全过：

1. 已提交 2 跳候选数 == 从行里数出来的 2 跳条数（66）；
2. 从 M9.2 边表数出来的路线集合 == 已提交的 66 个规范键，**不多一条、不少一条**；
3. 有序边对条数 == 2 × 66：同一个环有两个出发端，折叠轮转后只剩一条候选（§20 的
   「反向/轮转不折叠」差别在这里被量化）。

证人为什么是「M9.2 的已提交表」而不是「M3 的枚举器」——这是一次实测撞出来的边界：
第一版交叉验证确实是调用 M3 的 `enumerate_candidates` 当独立证人，为此给
`crates/discovery` 加了一条 dev-dependency。全量串行回归把它判红了：
`reconstruction_evidence_gate.rs` 的 `the_milestone_reads_canonical_history_and_stops_at_the_graph`
（`:3671-3684`）按 §29/§30 禁止 discovery 的 manifest 出现机会搜索的包名，
**且明写这条扫描连 `[dev-dependencies]` 一起算**，失败消息是「要删掉，不是解释」。
M9.3 的处理方式是不改前一个里程碑的门、也不留这条越界依赖：证人换成跨里程碑的已提交产物
（M9.2 的边表），它同样不调用本目录要验的那段生产码。见 §21 的红色记录。

审计第 3 节里「M3 的枚举器当独立对照用」这句已按上述事实改写。

## 23. Evidence Recompute（任务书 §53）

证据不靠 `cargo test` 自证。`pathfinder_evidence_gate.rs` 有一条**独立重算段**，
从 `raw/` 的原始记录 + M9.2 已提交的边表出发，不调用任何生产函数，重算：

`total`、`two_hop`、`three_hop`、`fee_complete`、`fee_incomplete`、`duplicate_cycles`、
`canonical_unique`、每条边是否在图内、每条候选的规范键是否等于自己边的最小轮转、
`chain_id`/`target_block` 是否等于图的。

测试 `the_independent_recompute_agrees_with_every_committed_number` 逐个字段比对已提交摘要。

四类篡改负控制（`an_injected_wrong_number_is_caught_by_the_recompute`），每类都先证明
「诚实版本是什么」再改：

1. 删掉一条候选 → 总数与深度计数变红；
2. 把一条候选的规范键换成它**自己的另一个轮转** → `canonical_unique` 变红
   （注意：单纯轮转是轮转不变的，改不出红，这是第一版控制犯的错，已换成本体不同的轮转）；
3. 给某条路线走过的**每条边**补上已举证费率 → `fee_complete` +1、`fee_incomplete` −1 变红
   （单补一条边不可能变红，因为一条补不齐一条环；这一版控制同样先断言该路线诚实状态是 `incomplete`）；
4. 删掉某条候选真正走过的那条边 → `edges_outside_the_published_graph` 变红。

字节门（§54）：`M93_EVIDENCE_REFRESH=1` 才写文件；普通运行逐字节比对，
任何一张表与 fresh rebuild 不一致即红（`every_committed_table_matches_a_fresh_rebuild`）。

## 26. Known Limitations

1. **0 条可定价候选**：全部 68 条候选的费率未举证，M9.3 产出的是形状清单，
   不是可交易清单。补齐费率属于 M11 之前的前置（审计 §7）。
2. **3 跳候选进不了财务层**：M3 的 `PricedCycle` 与 `Opportunity.hops` 都是 arity=2
   （审计 §4 / §20）。接口缺口已登记给 M11，M9.3 不动 M3。
3. **单块快照**：图是 37224031 那一块的投影，跨块不承诺稳定（NC8 把「不同块 = 不同身份」钉住）。
4. **无延迟目标**：`wall_ms` 31/32 只是装配那一次的记录，不构成任何性能基线（§43）。
5. **`states_visited` 无独立参照**：它是搜索自检量，未与外部暴力枚举对数；
   本轮的独立参照在候选集合层（§17 从 M9.2 边表独立数出的 2 跳路线集合，逐条与已提交规范键对齐）。
6. **证人换过一次**：2 跳集合最初的证人是 M3 的枚举器代码本身，但 discovery 的 manifest 被
   M9.2 的边界门禁锁住（连 dev-dependencies 都不许出现机会搜索的包名），所以现在的证人退到
   **M9.2 的已提交边表**——仍是跨里程碑产物、仍不调用被验的生产码，但它是「按同一套 §13 规则
   在门禁里重走一遍」，不是「另一段生产代码同意」。差别已写进 §17，不粉饰。
