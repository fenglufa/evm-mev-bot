```text

```

```text

```

# 4. Canonical State Semantics

For a target block:

```text
T
```

and a pool whose latest authoritative Sync is:

```text
S <= T
```

the state may be valid at T if and only if the system has sufficient evidence that no later authoritative Sync occurred between S and T.

Example:

```text
Sync @ 100
Target @ 120
No Sync 101..120
```

The pool's reserves at block 120 are the reserves from Sync @100.

This must NOT be confused with:

```text
Sync @ 121
Target @ 120
```

which is invalid for the target.

---

# 5. Do Not Use eth_call as a State Refresh Shortcut

For historical reconstruction:


It must not silently become the source of Graph market state.

The reconstruction search must start no earlier than necessary.

For a newly discovered pool:

```text

```

or another provably safe lower bound established by the existing state model.

Never scan the entire chain from genesis for every pool.

The target is:

```text
from <= Sync <= target
```

# 15. Graph Semantics

The Graph must remain a snapshot of one explicit block.

For:

```text

```

```text

```

```text

Pool B @ T-10
```

unless the state model can prove that B's state remained unchanged through T and represents it explicitly as state-at-T.

# 19. Negative Controls

At minimum implement:

### NC1 — Sync after target

```text
Sync @ 121
Target @ 120
```

Must not be selected.

### NC2 — No Sync

No authoritative Sync <= target.

Must remain unavailable.

### NC3 — Older Sync valid

```text
Sync @ 100
Target @ 120
No later Sync
```

Must be accepted as state valid at target if the semantic model supports this.

### NC4 — Multiple Sync same block

Must select canonical final event.

### NC5 — Future state leakage

A Sync after target must never affect target state.

### NC6 — Mixed-block Graph

A pool whose state cannot be proven valid at target must not enter the Graph.

### NC7 — getReserves fallback

Removing Sync evidence while leaving `getReserves()` available must NOT cause the pool to become graph-eligible.
