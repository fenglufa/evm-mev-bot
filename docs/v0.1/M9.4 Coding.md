# M9.4 Official Flashblocks Integration — Coding Agent Task

## 0. 任务目标

在现有 `evm-mev-bot` 基础上完成 **M9.4 Official Flashblocks Integration**。

本里程碑的目标不是交易、套利执行或利润计算。

本里程碑唯一核心目标：

> 将 GIWA 官方 Flashblocks 数据源接入系统，建立一个正确、可验证、可恢复的 Early-State / Early-Event Pipeline，使系统能够在 canonical block 最终确认之前识别“哪些链上对象正在发生变化”，并在 canonical block 到来后完成 reconciliation。

最终系统应能够：

```text
GIWA
 │
 ├── Canonical RPC
 │
 └── Flashblocks WS
          │
          ↓
   FlashblocksProvider
          │
          ↓
   Protocol Decoder
          │
          ↓
   Sequence Validation
          │
          ↓
   Early Events
          │
          ↓
   Affected Pools
          │
          ↓
   Canonical Verification
          │
          ↓
      StateStore
          │
          ↓
    GraphSnapshot
          │
          ↓
      M9.3 PathFinder
```

### 核心原则

```text
Flashblocks = Early Radar
Canonical RPC = Final Judge
```

必须严格保证：

```text
Flashblocks ≠ Canonical State
Flashblocks ≠ Execution Authorization
Flashblocks ≠ Profit
Flashblocks ≠ Final Chain Truth
```

# 3. 最重要的架构约束

## 3.1 Flashblocks 不得直接写入 Canonical StateStore

```text

    ↓

```

禁止将 Flashblocks-derived state 伪装成普通 `PoolState`。

必须保持：

```text
Flashblocks
    ↓

    ↓

    ↓

```

# 4. Canonical State 与 Preconfirmation State 必须类型隔离

现有：

```text
PoolState
```

继续代表：

> 某个 canonical block 上已经确认的池状态。

M9.4 新增的临时状态应采用独立类型，例如：

```rust
PreconfirmationState
```

或等价的明确命名。

禁止设计成：

```rust
PoolState {
    source: Rpc | Flashblocks
}
```

原因：

类型层面必须能够防止：

```text
Flashblocks state
    ↓
误当成
    ↓
Canonical PoolState
```

# 8. Flashblock Identity

必须建立明确的 Flashblock identity。

概念：

```rust
FlashblockIdentity {
    chain_id,
    block_number,
    index,
    parent_identity,
}
```

Identity 必须能够区分：

```text

```

不能只使用：

```text

```

# 9. Sequence Validation

Flashblocks stream 必须进行严格 sequence validation。

正常：

```text
0
1
2
3
4
```

必须支持识别：

### Duplicate

```text
0
1
2
2
3
```

第二个 `2` 不得重复 apply。

---

### Gap

```text
0
1
3
```

必须识别：

```text
GAP_DETECTED
```

不能直接：

```text
2 → 3
```

---

### Wrong block

```text
block 100 / index 3
block 101 / index 4
```

如果当前 block sequence 未完成，不得直接拼接。

---

### Wrong parent

如果协议提供 parent identity：

```text
expected parent != received parent
```

必须：

```text
reject / reset / recovery
```

具体行为必须由协议语义决定，但绝不能继续构造错误的 preconfirmation state。

# 17. Reconciliation Mismatch

如果：

```text
Flashblocks = X
Canonical = Y
```

必须：

```text

```

不能：

```text

```

不能：

```text

```

除非存在明确协议语义证明二者其实是不同阶段的合法状态。

最终 canonical state 必须由 canonical source 决定。

必须拒绝。

无 AMM 影响的 transaction。

不得产生 AffectedPool。

## NC11 Reverted Transaction

reverted transaction 不得被当成成功 state mutation。

## NC12 Same Pool Multiple Changes

同一个 block 中：

```text
Pool A
Pool A
Pool A
```

必须正确识别，不得因为简单 set dedup 而丢失必要 event identity。

# 61. 最终系统语义

M9.4 完成后，系统应该能够严格表达：

```text
Flashblocks observed something early.
        ↓
We validated its protocol identity.
        ↓
We validated its sequence.
        ↓
We identified affected pools.
        ↓
We did NOT treat this as canonical state.
        ↓
Canonical block arrived.
        ↓
We reconciled.
        ↓
Canonical state became authoritative.
        ↓
Existing Graph / PathFinder pipeline may consume it.
```

最终必须保持：

```text
EARLY ≠ FINAL
OBSERVED ≠ VERIFIED
VERIFIED ≠ CANONICAL
CANONICAL ≠ PROFITABLE
```

这四个边界不能因为 Flashblocks 的低延迟优势而被打破。
