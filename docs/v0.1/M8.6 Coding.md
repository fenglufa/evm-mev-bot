
# 1. M8.6 的真正目标

不要再问：

> “哪里还能缓存？”

改成：

> **“当前生产热路径的每一次 RPC，是否存在一个不改变系统语义的 RPC reduction opportunity？”**

最终需要得到一个完整的 RPC Reduction Census：

```text
RPC
 ↓
阶段
 ↓
调用者
 ↓
语义类型
 ↓
identity
 ↓
是否重复
 ↓
是否可复用
 ↓
是否承担 verification
 ↓
是否可以传播
 ↓

 ↓

 ↓
理论最大节省
 ↓
真实可实现节省
 ↓
风险
 ↓

```

最终不是必须找到优化。

允许最终结论：

```text

```

```text

```

# 2. M8.6 核心原则

## 2.1 correctness > verification > freshness > RPC saving

任何候选必须满足：

```text
不删除独立 verification
不降低 freshness
不改变 canonical authority
不改变交易语义
不改变风险边界
```

之后才能讨论：

```text
RPC saving
```

---

## 2.2 duplicate != reusable != safe-to-reuse

必须始终保持三层：

```text
duplicate
    ↓
reusable_in_principle
    ↓
safe_to_reuse_now
```

任何一层都不能直接推导下一层。

---

## 2.3 propagation != reuse

M8.4.4 已经证明：

```text
block context
    ↓
可以安全传播
```

但：

```text
safe propagation
≠
RPC saving
```

因此本阶段不要因为某个 context 可以跨阶段传播，就把它标成 RPC reduction candidate。

---

## 2.4 不允许为了发现 candidate 而新增 RPC

本阶段原则：

```text
existing evidence first
```

优先使用：

* M8.2 RPC trace
* M8.3.1 state reuse evidence
* M8.3.2 post-reuse trace
* M8.3.3 concurrency evidence
* M8.4.1 pipeline RPC census
* M8.4.2 cross-stage candidates
* M8.4.3 ownership/lifecycle matrix
* M8.4.4 block-context evidence
* M8.5.1 eth_call evidence

如果现有 evidence 不足以证明某个候选：

```text
NOT_ENOUGH_EVIDENCE
```

而不是偷偷增加 RPC。

# 8. 重点检查五种 RPC Reduction Pattern

## Pattern A：真正重复读取

例如 M8.3.1：

```text
same simulation
same chain
same block
same address
same slot
same semantic request
```

如果发现：

```text
duplicate > 0
```

继续判断：

```text
same owner?
same lifecycle?
same freshness?
same authority?
```

---

## Pattern B：跨阶段相同 canonical read

例如：

```text
Detection
   ↓
Preflight
```

但必须区分：

```text
ordinary repeated read
```

与：

```text
independent verification
```

M8.5.1 的 `eth_call reserves` 已经属于后者。

因此不能重复研究。

---

## Pattern C：Block context propagation

例如：

```text
Observation
   ↓
Preflight
   ↓
Build
```

如果只是：

```text
同一个 block header
```

可以传播，但 M8.4.4 已证明当前：

```text
net RPC saving = 0
```

因此必须标记：

```text
SAFE_PROPAGATION_NO_SAVING
```

不能重新列为 candidate。

---

## Pattern D：Protocol oracle

重点检查：

```text
getL1Fee(bytes)
```

但必须区分：

```text
same calldata
different calldata
same block
different block
```

不能因为：

```text
oracle
```

就假定可以缓存。

必须调查：

```text
input identity
block dependency
contract/precompile dependency
freshness
```

如果没有证据：

```text
NOT_ENOUGH_EVIDENCE
```

不要实验。

---

## Pattern E：Preparation reads

重点检查：

```text
nonce
fee
balance
block/header
```

但必须严格区分：

```text
read needed for safety
```

与：

```text
read needed only because previous stage failed to carry information
```

例如：

```text
nonce
```

不能因为前后阶段读取相同，就直接认为重复。

因为 nonce 可能发生：

```text
local execution
another tx
pending tx
external actor
```

导致 freshness 改变。

```text

AND

```


### P2


```text

```

例如：

```text

block-sensitive without safe freshness
```

```text

```

# 33. 特别要求：不要为了“继续 M8”强行找优化

如果最终发现：

```text
State Read Reuse
        ↓
已消灭真正 duplicate

Concurrency
        ↓
已消灭部分 wall-time

Block propagation
        ↓
safe but zero RPC saving

Detection → Preflight eth_call
        ↓
verification 必须保留

L1 Fee
        ↓
当前无 duplicate

Nonce / Fee / Balance
        ↓
freshness / safety 仍需要独立判断
```

那么完全可以得到：

```text
NO_SAFE_RPC_REDUCTION_FOUND
```

这不是失败。

这意味着：

> **M8 已经从“寻找明显重复 RPC”进入“剩余 RPC 大多具有业务语义”的阶段。**

此时继续优化的主要方向就不再是：

```text
RPC elimination
```

而可能应该转向：

```text
RPC latency
endpoint architecture
connection strategy
provider selection
regional deployment
sequencer proximity
request scheduling
execution-path redesign
```

但这些必须等 M8.6 完成后再决定。

# 35. 最终原则

本阶段最重要的一句话：

> **不要寻找“可以少打一条 RPC”的地方，要寻找“在原有安全语义完全不变的情况下，本来就不需要打这条 RPC”的地方。**

只有后者才是我们真正要的优化。
